# 评分、登录与并发验证

## 本次行为

- 每次有效答题只调用一次评分模型，返回一个 `score`、文字反馈及备用追问。评分配置使用 `SCHOOL_LLM_SCORER_PROMPT`，为空时继承默认提示词；出题仍使用 `SCHOOL_LLM_INTERVIEWER_PROMPT`。
- 以题目实际要求和知识库为主要依据，认可语义等价表述。学生的相关、可靠库外拓展或替代解法可计入同一个总分，不另列拓展分；无法核实的内容不臆断为错误，拓展不能掩盖核心错误。反馈须标明采用了“拓展判断”，不泄露标准答案。
- 管理端只显示一个得分。历史数据不重算；为兼容旧数据库和接口，新记录的 `interviewerScore`、`scorerScore`、`averageScore` 保存同一个分数。
- 在完整的启用知识库条目中先按当前知识点匹配，再应用条数上限；没有匹配时回退到基础材料。材料去重，单次最多 8,000 个 Java 字符，截断时明确标注节选。该限制是字符预算，**不是精确 tokenizer 计数**。
- 删除第二次评分调用，减少重复发送题目、答案和知识库；原先两次各最多 20,000 字符的知识材料，现在评分只发送一份最多 8,000 字符的材料。实际 token 节省比例取决于材料长度、配置和所用模型，不能用字符数直接代替 token 数。
- 学习诊断复用已有逐题反馈，优先提取薄弱题目，最多八条、每条 220 字符；不再次发送整份知识库，不根据分数推测具体错误。
- 首次加载页面通过 `/api/auth/me` 恢复 Cookie 会话。未改密用户访问首页、登录页、注册页、考试页或删除改密 URL 后，都会进入 `/change-password`；兼容 `/changepasswd`。后端继续阻止未改密用户访问考试，返回明确的 `PASSWORD_CHANGE_REQUIRED`，前端据此恢复跳转。

## 并发设置

`INTERVIEW_LLM_WORKERS=16`、`INTERVIEW_LLM_QUEUE_CAPACITY=120` 控制出题和现有流式任务的线程池，修改后需要重启。原先核心线程为 2，队列未满时不会扩展到最大线程数，因此 60 人同时开考会大量排队。

学生当前使用普通答题提交接口，其 LLM 调用在 HTTP 请求线程上执行，**上述线程池不是整个应用的模型并发限流器**。同时提交 60 份答案仍可能产生约 60 个上游评分请求。部署时需要检查模型服务实际的并发数、RPM、TPM 额度，以及响应时间；本机模拟模型不能验证这些限制。

## 可重复运行的测试

```sh
mvn -pl backend -Dtest=ExamConcurrencyTest -Dexam.load.llmDelayMs=3000 test
cd frontend
npm test
npm run build
```

`ExamConcurrencyTest` 自动创建隔离的临时 SQLite 数据库、随机端口的真实 Spring Boot HTTP 服务与本机模拟 LLM，不使用实际模型密钥，也不修改业务数据库。默认模拟模型延迟 250 ms，参数可改为 3,000 ms 等值；后端普通模型请求原有超时是 15 秒。

测试为 60 名学生同时登记、开考，每人答两轮；每轮使用同步屏障让 60 人同时提交，并逐个重试相同答案。默认覆盖首次登记时的账户创建与 BCrypt 密码哈希，也可加 `-Dexam.load.preboundAccounts=true` 测已有账号。覆盖 JWT 认证、CSRF、数据库事务、出题队列、轮询、心跳、评分、结果分析。额外放置 101 条不相关知识，确认其后的相关条目仍进入评分上下文。测试轮询间隔为 200 ms，比当前前端的 2.5 秒更密集。

断言包括：120 份完成的答案、恰好 120 次评分模型调用、120 次出题、60 次学习诊断、60 名不同学生的最终成绩均正确；重复请求不增加评分调用。程序成绩的真实来源为 `school_exam_process` 和 `school_answer_record`，旧的 `school_exam_attempt` 汇总字段不作为完成判断依据。

每次通过后生成 `backend/target/exam-load-report.txt`，记录各阶段请求数及 P50、P95、最大耗时。不含浏览器渲染、防作弊视频上传、真实模型质量、生产网络或长时间持续压测。

## 本机实测（2026-09-29）

Windows、JDK 21、真实 SQLite 单连接池、16 个出题工作线程；模拟模型每次固定等待 3 秒。60 名首次登记学生完成两轮，全流程耗时 66.31 秒，7,735 次 HTTP 请求全部成功。120 份答案与 60 份最终成绩均正确，120 次重复提交未增加评分模型调用。

| 请求阶段 | 请求数 | P50 | P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| 首次登记（含创建账号） | 60 | 5.494 s | 8.343 s | 8.645 s |
| 开考 | 60 | 4.785 s | 6.940 s | 7.887 s |
| 答案评分 | 120 | 3.962 s | 4.571 s | 4.728 s |
| 重复提交 | 120 | 0.538 s | 1.091 s | 1.469 s |
| 学习诊断 | 60 | 3.096 s | 3.668 s | 3.831 s |
| 心跳 | 120 | 0.042 s | 0.279 s | 0.443 s |
| 题目轮询 | 7,195 | 0.030 s | 0.217 s | 2.607 s |

另一次已有账号的同规模测试中，评分 P95 为 3.964 秒、登记 P95 为 0.797 秒。首次登记包含 BCrypt 开销，明显更慢，且最大耗时已接近前端默认 10 秒请求超时；上述通过结果不能保证更慢的生产机器也有相同余量。

后端全量回归通过，随后最终评分配置和首次登记场景的专项测试也通过；累计 127 个后端测试、13 个前端测试均通过，前端生产构建通过。模型输出由测试服务固定提供，因此这里只验证链路、提示词组装和数据一致性，不代表真实模型评分质量已获验证。
