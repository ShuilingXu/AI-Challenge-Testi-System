# P1 考试可信度修复

## 考试窗口

考试开放区间为 `[publish_start, publish_end)`；未设时间边界时不限制该边界。开考、恢复、取题、领取评分任务和提交评分结果均校验发布状态、当前窗口和班级匹配。领取任务和评分落库在事务内锁住考试行，使教师关闭/修改考试与成绩提交按数据库写入顺序执行，模型调用期间不持锁。

模型返回前考试已关闭或截止时，评分事务回滚，不写单题分数、不更新流程均分和及格结论。已领取的原始答案保留，任务标为 `FAILED`（`GRADE_NOT_COMMITTED`）；教师重新开放考试后，学生可用相同答案重试。历史成绩和答题记录仍可查询。本次没有加入自动收卷，也无法追溯修复前哪些分数是在截止后写入的。

## 教师作用域和升级安排

未指派负责教师的考试只对管理员开放。教师新建考试须选择自己的授课班级，并自动成为该考试负责教师；教师不能自行更改负责教师和学生成绩可见性。

新增 `school_class_teacher` 记录授课班级。管理员在班级管理页分配授课教师；教师只可查询、添加、编辑和导入所教班级学生。学生改班时同时校验原班级和目标班级。班级维护、班级导入、班级/学生删除仅限管理员。名册变更记录审计。

升级后旧班级没有授课教师，旧的无负责教师考试也不再对全体教师开放。请管理员在班级管理页和考试管理页明确指派；不根据历史访问记录推断权限。迁移器通过现有 `schema.sql` 加载流程创建新关系表，已有数据保留。

## 成绩可见性

学生流程、心跳、答题记录、交卷响应、考试列表和历史列表遵循同一实时/最终成绩开关。隐藏时清除分数、评语、及格分和追问阈值；结束状态统一为 `COMPLETED`、文案为“答题已提交”，避免 `REJECTED`、阶段状态或结论文案直接泄露不及格结果。教师接口保留真实状态。

## 录像存储

默认单流程最多 512 MiB、720 段，单段仍最多 100 MiB；编号范围为 0–719。每账号每分钟最多 20 次上传，使用现有 Redis 限流存储，Redis 不可用时拒绝上传。相同段替换按替换后的总字节数计算，实际文件（包括历史文件和数据库失败留下的文件）计入总量；流读取也按声明大小及配额封顶。

上传事务锁住流程行后校验配额，避免多个后端实例同时突破同一流程配额。多个实例须共用录播目录。配置见 `.env.example` 中 `SCHOOL_RECORDING_*`。默认磁盘保留 1 GiB，触及保留空间时拒绝写入并输出 `Recording disk reserve reached` 的 WARN 日志；运维应将此日志接入告警，并另行监控磁盘可用空间。长考试需根据实际码率提前评估配额，不能仅按分段数推算容量。

## 知识库和人工复核

JSON 新建/更新与 Excel、CSV 导入均调用同一注入检查，同时加入“给所有学生满分”等评分操纵指令的规则。该检查只能拦截已知指令形式，不能保证模型抵抗所有提示注入，结构化不可信输入和分数校验也不保证评分语义正确。

AI 单题评分达到 90 分且尚未人工复核时进入待复核提示：教师成绩列表显示题数，逐题显示提示；保存人工复核后清除该标记。此标记不阻断成绩发布或自动及格判定，教师仍须完成核验。AI 评分用于辅助评估，正式考试应配合教师复核和抽查。

## 验证

新增行为测试覆盖考试窗口内外、模型执行中关闭/截止、标准和模板流程、无负责教师的越权、所教班级的名册范围、学生隐藏成绩、JSON 注入、录像总量/段数/替换/限流/低磁盘/并发上传。

事务、迁移和并发行为使用真实 SQLite 验证，未在本次运行 PostgreSQL/MySQL 集成测试。录像限流验证复用了 Redis 限流服务的调用和拒绝行为，未在本次启动真实 Redis 执行 Lua 脚本。
